# AGENTS.md — Pillshelf

Інструкції для AI-агентів і нових розробників. Android-застосунок на Kotlin +
Jetpack Compose (Material 3), Room, WorkManager, OkHttp. Offline-first трекер
домашньої аптечки. Весь UI і коментарі — українською.

## Команди

```bash
./gradlew assembleDebug        # зібрати debug APK
./gradlew testDebugUnitTest    # юніт-тести (мають бути зелені ЗАВЖДИ)
./gradlew installDebug         # на підключений пристрій
```

- `local.properties` містить лише `sdk.dir`; він у `.gitignore`.
  У цьому репо не зберігаються секрети збірки — релізний підпис приходить
  env-змінними в GitHub Actions (див. `.github/workflows/release.yml`).
- CI: `testDebugUnitTest` виконується ПЕРЕД `assembleRelease`; червоні тести
  ламають реліз. Не вимикати цей порядок.

## Структура

- `data/model` — Room-сутності; `data/local` — DAO + `PillshelfDatabase`;
  `data/remote` — клієнт tabletki.ua; `data/repository`, `data/export`.
- `domain/usecase` — чиста логіка (планувальник, тренди, взаємодії).
- `service` — будильники, воркери, сповіщення, налаштування.
- `ui` — Compose-екрани, компоненти, `PillshelfViewModel`.
- `app/schemas/` — експортовані схеми Room. **Завжди комітити** разом зі
  зміною версії БД (`exportSchema = true`, `ksp.arg room.schemaLocation`).
- `spec.md` — рішення щодо нагадувань. Змінюєш планувальник — онови і його.
- `docs/BREAKAGE_LOG.md` — журнал поломок. Злам щось у збірці/CI — додай запис.

## Медичні інваріанти (порушувати НЕ МОЖНА)

1. **Ніколи не генерувати дані, що виглядають як реальні.** Ні цін аптек,
   ні назв/адрес аптек, ні прийомів, ні «демо-препаратів». Порожній стан із
   поясненням завжди кращий за вигадку. Fallback-код не має фабрикувати дані.
2. **Нагадування лише через точні будильники** (`setAlarmClock`;
   fallback — `setAndAllowWhileIdle` зі статусом у UI). WorkManager — тільки
   страховий канал, не основний.
3. **Будь-яка порада щодо ліків супроводжується дисклеймером**
   «не замінює лікаря чи фармацевта». Підказки щодо взаємодій — це кілька
   вбудованих правил; текст завжди каже «це НЕ повна перевірка».
4. **Жодних медичних висновків або дозувань «за замовчуванням».** Застосунок
   обліковий: фіксує те, що ввів користувач, і не «виправляє» його дані.
5. **Дані про здоров'я не залишають пристрій без явної дії користувача.**
   Моніторинг цін вимкнений за замовчуванням; увімкнути може тільки людина.
6. Зберігай чесний порожній стан цін: якщо API недоступний — «ціни
   недоступні» + перехід на сайт, а не заглушки.

## Конвенції

- Kotlin офіційний стиль; Compose M3; кольори статусів — з `ui/theme` (не хардкод).
- Час: `java.time`; у use-case'и час ін'єктується параметром (див. `now` у
  `CalculateNextIntakeUseCase`) — тести мають бути детермінованими.
- Тести: JUnit4, імена-речення українською у зворотних лапках, без ->
  в іменах (Kotlin забороняє `>` у назвах функцій).
- Не комітити: `.env`, `*.keystore*`, `local.properties`, `*.jks*`,
  `release-signing-credentials.txt`. Комітити: `app/schemas/` при зміні БД.
- README (укр + англ) тримати згодним із кодом; перш ніж описувати фічу —
  перевір, що вона не «вигадана» fallback-кодом.
