# Журнал поломок — Pillshelf

Формат запису: **Симптом → Причина → Фікс → Урок/профілактика**.
Додаємо запис, щойно щось зламалось у збірці, CI чи рантаймі — навіть якщо
вилікували одразу. Мета: поломка не має вчитися двічі.

---

## 2026-09-20 — assembleDebug падав на чистому клоні

- **Симптом:** будь-яка збірка на свіжому клоні завершувалась помилкою signing.
- **Причина:** `buildTypes.debug` мав `debugConfig`, що вказував на
  `${rootDir}/debug.keystore` — файл під `*.keystore` у `.gitignore`, у git його не було.
- **Фікс:** debug-конфіг прибрано; AGP підписує debug власним
  `~/.android/debug.keystore`.
- **Урок:** не посилатися в конфігурації на файли, яких немає в git; перевіряти
  збірку саме на чистому клоні перед пушем (для цього й існували коміти
  `test: temporary clean-clone debug build check`).

## 2026-09-20 — Флакаючий NPE в AWT-EventQueue під час KSP у CI

- **Симптом:** CI падав через раз із NPE в embedded IntelliJ core всередині KSP.
- **Причина:** сумісність версій Kotlin/KSP із AWT на headless-раннері.
- **Фікс:** оновлення Kotlin 2.2.10 → 2.3.20 і KSP 2.3.5 → 2.3.12; прапорець
  `org.gradle.jvmargs=-Djava.awt.headless=true` лишено як гігієну.
- **Урок:** флакаючий CI — це теж поломка; фіксити оновленням версій, а не retry.

## 2026-09-20 — Застосунок показував вигадані ціни аптек

- **Симптом:** екран «Ціни» завжди заповнений цінами 5 аптек з адресами;
  тренди рахуються. Реальні дані при цьому ніхто не отримував.
- **Причина:** `TabletkiApiClient.generateBenchmarkPrices()` підміняв
  недоступний API фабрикацією «benchmark»-цін; `tabletki.ua/api/search`
  віддає HTTP 403 (Cloudflare) не-браузерним клієнтам.
- **Фікс:** генератор видалено; клієнт повертає порожній список; UI показує
  «ціни недоступні» + кнопку на tabletki.ua; у БД лише реально отримані записи.
- **Урок:** fallback-код не має вигадувати дані. Порожній стан із поясненням —
  це фіча, а не баг. Запис у `AGENTS.md` (медичні інваріанти).

## 2026-09-20 — AS_NEEDED планувався як звичайний розклад

- **Симптом:** препарат «за потреби» отримував би нагадування за слотами дня.
- **Причина:** у `CalculateNextIntakeUseCase` невідома scheduleType потрапляла
  в else-гілку `calculateDailyIntake`; UI не давав створити AS_NEEDED, тому баг
  не проявлявся.
- **Фікс:** явна гілка AS_NEEDED → null; режим додано в форму редагування;
  інваріант закрито тестами.
- **Урок:** замість else-гілки — явна обробка кожного режиму; режим має бути
  досяжним з UI, інакше код мертвий або непротестований.

## 2026-09-20 — Нагадування спізнювались або не приходили

- **Симптом:** єдиний канал — WorkManager кожні 15 хв із вікном ±15 хв:
  нагадування приходили з запізненням до 15 хв або не приходили в Doze.
- **Причина:** AlarmManager не використовувався взагалі.
- **Фікс:** `ReminderScheduler` на `setAlarmClock()` (+fallback
  `setAndAllowWhileIdle`), фіналізація пропущених доз через 30 хв,
  відновлення після reboot (`BootReceiver`), статус дозволу в UI.
- **Урок:** для ліків «нагадування приблизно вчасно» — це поломка; точні
  будильники + явний стан дозволу обов'язкові.

## 2026-09-20 — Тести планувальника залежали від реального годинника

- **Симптом:** 3 з 16 тестів падають залежно від часу доби запуску.
- **Причина:** юзкейс читав `LocalDateTime.now()` всередині; тесті задавали
  фіксовані «сьогодні», що не збігається з реальним now.
- **Фікс:** `now` став параметром із дефолтом; тести повністю детерміновані.
- **Урок:** будь-яка залежність від поточного часу в логіці — ін'єкція.
  Червоний CI ламає реліз (крок тестів перед assembleRelease).

## 2026-09-20 — Демо-дані виглядали як реальна історія пацієнта

- **Симптом:** свіжа інсталяція містила прийоми («Ранковий прийом після їжі»),
  ціни та препарати, яких ніхто не додавав.
- **Причина:** `seedInitialData` сідував 5 «реалістичних українських» препаратів
  з історією цін і прийомів.
- **Фікс:** сідаються лише стандартні категорії фільтрів; аптечка стартує порожньою.
- **Урок:** у медичному застосунку навіть «демо» — це дані про здоров'я;
  користувач має бути автором усіх своїх записів.
