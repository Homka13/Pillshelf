# SPEC — Нагадування та облік прийомів

> Цей документ — джерело правди про те, як працюють нагадування та розрахунок
> споживання в Pillshelf. Будь-яка зміна логіки планувальника має оновлювати
> цей файл у тому ж коміті.

## Явні рішення

1. **Графік рухається від сповіщення (факту прийому), а не від календаря.**
   Час наступної дози рахує `CalculateNextIntakeUseCase.calculateNextIntake()`:
   для `DAILY`/`COURSE` — наступний слот часу дня з урахуванням `lastIntake`,
   для `EVERY_N_HOURS` — `lastIntake + interval`. Точка відліку `now`
   ін'єктується (у продакшені — поточний час) — це робить тесті детермінованими.

2. **Споживання рахується з історії прийомів**, а не з розкладу чи будильників.
   Джерело — таблиця `intake_history` (записи «Прийнято» / «Пропущено» /
   «Прострочено»). Adherence = прийнято / (прийнято + пропущено + прострочено).
   Розклад (`ScheduledDoseItem`) — лише відображення плану, не лічильник.

3. **Основний канал нагадувань — точні будильники `setAlarmClock()`**
   (`ReminderScheduler`). Вони не підпадають під Doze і показують системну
   іконку будильника. `ReminderWorker` (кожні 15 хв) — страховка, не основа.

4. **Пропущена доза не зникає.** Якщо протягом `GRACE_MINUTES` (30 хв) після
   часу дози прийом не відмічено, `AlarmReceiver` (ACTION_FINALIZE_MISSED)
   пише в журнал запис «Прострочено» і планує наступну дозу.

5. **`AS_NEEDED` не планується.** Жодних будильників і слотів; прийоми
   фіксуються вручну. `dosesPerDay()` для нього повертає 0.

6. **Нульовий залишок скасовує будильники** на рівні юзкейса:
   `calculateNextIntake()` повертає `null`, `ReminderScheduler` прибирає
   будильники; UI додатково блокує кнопку прийому. Після поповнення план
   відновлюється спостерігачем у MainActivity.

7. **«Відкласти» = рівно +15 хвилин** від запланованого часу
   (`SNOOZE_MINUTES` у `PillshelfViewModel`), через точний будильник.

8. **Дозвіл точних будильників** показується банером на екрані аптечки;
   запит — через `ACTION_REQUEST_SCHEDULE_EXACT_ALARM`. Без дозволу —
   fallback `setAndAllowWhileIdle()` (може спізнюватися, про це сказано в UI).

9. **Після перезавантаження** `BootReceiver` відновлює будильники для всіх
   препаратів із розкладом (WorkManager відновлює свою періодику сам).

## Карта компонентів

| Файл | Відповідальність |
|---|---|
| `domain/usecase/CalculateNextIntakeUseCase.kt` | Час наступної дози, `dosesPerDay()` |
| `service/ReminderScheduler.kt` | Точні будильники: планування, snooze, cancel, стан дозволу |
| `service/AlarmReceiver.kt` | Сповіщення про дозу; фіналізація «прострочено» |
| `service/BootReceiver.kt` | Відновлення будильників після reboot |
| `service/ReminderWorker.kt` | Страховий огляд розкладу (15 хв) |
| `ui/viewmodel/PillshelfViewModel.kt` | `snoozeDose`, `recordIntakeRetroactive`, список доз і прострочень |
